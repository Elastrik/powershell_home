# Architecture condensée (powershell_home)

Vue d'ensemble volontairement courte, basée sur un `tree` retravaillé à la main puis
corrigé par lecture réelle du disque (26/11/2026). Les arborescences ci-dessous sont des
**exemples représentatifs, pas des listes exhaustives** : de nouveaux Core, App ou profils
peuvent exister sans figurer ici.

Contenu identique maintenu dans `.clinerules/10_architecture.md`.

## Racine

```
powershell_home/
├── core/      # Fondations techniques — ne dépend jamais de app/
├── app/       # Applications installées — peuvent dépendre de core/
├── home/      # Profils utilisateurs + point d'entrée (home/profile/)
├── install.ps1     # Crée un nouveau profil
├── launcher.ps1    # Lance core/profile/apploader.ps1 pour le profil actif
└── architechture.txt
```

## core/ (exemples réels)

```
core/
├── menu/              # core.ps1, menu.ps1 (classes Menu/MenuItem), config/
├── welcome/           # core.ps1, welcome.ps1 (classe Welcome), config/
├── database/          # core.ps1, dbmanager.ps1 (classe DataBaseManager), config/
└── profile/
    ├── apploader.ps1  # pilote le chargement : common -> Core (core.txt) -> App (app.txt) -> profil
    └── common/config/ # variables/functions/alias chargés avant tout Core/App
```

Chaque module Core suit : `core.ps1` → `config/variables.ps1` → classe(s) métier
éventuelle(s) → `config/functions.ps1` → `config/alias.ps1`.

## app/ (exemples réels)

```
app/
├── sailor/            # app.ps1, config/, modules/
│   └── modules/
│       ├── core/      # bag, dockMap, merchant, wallet — coeur interne de sailor
│       └── app/       # bigfish, cargo — sous-applications de sailor
└── llm/               # app.ps1, config/, modules/core/LlmCore.ps1
```

Chaque App suit : `app.ps1` → `config/variables.ps1` → `config/functions.ps1` →
`config/alias.ps1`. Une App peut posséder sa propre hiérarchie interne `modules/core/` et
`modules/app/` (cf. sailor) ; les mêmes règles Core→App s'y appliquent en interne.

## home/profile/<Profil>/ (exemples réels : default, KERHIS)

```
home/profile/<Profil>/
├── core.txt           # liste des Core à charger
├── app.txt            # liste des App à charger
├── config/
│   ├── variable.ps1   # ⚠️ singulier — exception propre au profil uniquement
│   ├── functions.ps1
│   ├── alias.ps1
│   ├── logo.ps1
│   ├── welcome.ps1
│   └── main.menu.json # menu principal (commande mmm)
└── persistent/        # données sauvegardées par les apps (ex: wallet.json, docks.json)
```

## Règles invariantes

- Core ne dépend jamais d'App ; tous les Core sont chargés avant les App (`apploader.ps1`).
- Ordre de chargement d'un module : `variables.ps1` → `functions.ps1` → `alias.ps1`.
- Seul `home/profile/<Profil>/config/variable.ps1` est au singulier ; partout ailleurs
  (Core, App, modules internes) c'est `variables.ps1` (pluriel).
